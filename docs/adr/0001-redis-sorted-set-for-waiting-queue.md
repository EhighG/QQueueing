# 대기열 저장소로 Kafka 대신 Redis Sorted Set을 쓴다

대기열에는 줄 서기, 순번 조회, 이탈, 입장(앞에서 N명), 대기 인원 조회, 초기화가 필요하다. 이 가운데 순번 조회는 대기자마다 1초에 한 번씩 호출하므로 가장 잦은 연산이다. Kafka는 순번 조회도, 줄 중간에서 빼는 이탈도 지원하지 않는다. 그래서 순번 계산과 이탈 기록을 main 메모리에서 직접 했고, 그 결과 재시작하면 대기자가 모두 사라지고, main을 여러 대 띄울 수 없고, 대기열 수가 파티션 수(20)로 묶였다. Redis Sorted Set은 이 연산들을 각각 명령 하나로 처리한다(`ZADD`, `ZRANK`, `ZREM`, `ZPOPMIN`, `ZCARD`, `DEL`). 이탈과 입장이 순번에 바로 반영되고, 상태가 main 밖에 있으므로 재시작해도 남고 나중에 여러 인스턴스가 함께 쓸 수도 있다. 그래서 Redis Sorted Set을 쓴다.

## Considered Options

- **Kafka 유지**: 순번 계산, 이탈 기록, 그 상태의 저장을 직접 구현해야 하고, 그 상태를 둘 저장소가 따로 필요하다. Kafka의 강점인 대량 순차 기록, 여러 소비자의 독립 소비, 재처리는 대기열에서 쓰이지 않는다.
- **RabbitMQ**: 작업 큐라서 메시지의 위치를 묻거나 중간 메시지를 빼는 연산이 없다. 소비하면 메시지가 사라지고 오프셋도 없어, 입장한 인원까지 직접 세야 한다.
- **Redis pub/sub, Redis Streams**: pub/sub은 메시지를 저장하지 않으므로 줄을 담을 수 없다. Streams는 로그 구조라 순번 조회가 없다.

## Consequences

- Redis는 AOF `appendfsync everysec`로 named volume에 기록한다. Redis가 비정상 종료되면 최대 1초 동안 들어온 줄 서기를 잃는다.
- 대기자 전원이 메모리에 올라간다. 대기자 100만 명에 대략 100~200MB다.
- Kafka 소비를 HTTP로 감싸던 consumer 서버는 필요 없어진다.
- 여러 명령을 묶는 연산(예: 앞에서 꺼내기와 입장 기록)은 Lua 스크립트나 `MULTI`로 원자성을 지킨다.
